# B44: Every product's console follows the security switch

**Group:** B. Board descriptions

**Needs:** B13

The ruling (user's security rule, relayed by the coordinator on 2026-11-23): security off means fully open. Off, root
logs in on the console with no login step, as it does over USB and Ethernet. On, a login is required, and never one
with an empty password. The console follows the switch. An unconditional "no empty-password console in a product" would
contradict that rule, so it is not what this item checks. (The first brief asked for exactly that; it is replaced.)

## What is on next (a98a2cf6)

- raze-base gates every getty on the switch:
  - `devices/components/raze-base-files/files/console-allowed` is the `ExecCondition=` of a drop-in on the three
    getty templates (serial-getty@, getty@, autovt@). It reads the board's security view, /etc/board/security.
  - A view that is absent, or "off", starts the getty (open root console). A view that is "on", or malformed, skips
    it (no login at all).
- `scripts/check-console-gate.py` runs the script against every view case and checks that the three drop-ins are
  installed. The gate runs it. It checks raze-base-files only.

## Build

- The check covers every product, not one component.
  - Any product whose image starts a getty or autologin on any tty must install the switch's gate on every getty
    template it uses.
  - It reads the planned root (the enabled units, the drop-ins, passwd and shadow), not comments.
  - A product with no console at all passes.
- On, never an empty password: with the view "on", no console may let root in with an empty password. Today "on"
  means no login at all on the console, and that passes. If "on" is to mean "login required" (a prompt that takes a
  credential), the credential is not the empty password and not a password baked into the image. That is the
  Orion login helper (C52), or another form the owner names. Ruling (coordinator, 2026-11-23): security on means logins and keys,
  so the target for "on" is a real login through Orion's login helper (C52). Today's "no login at all" is an
  acceptable interim and is recorded as one. The check holds both forms to "never empty".
- The check's self-test has three cases:
  - a product that starts a getty without the gate is refused;
  - a gate that opens the console under "on" is refused;
  - raze-base passes.

## Proof

`scripts/check-console-gate.py --self-test` (or its successor) refuses the three bad cases and passes every product
on next. The gate runs it.
