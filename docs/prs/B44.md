# B44: No root console with an empty password in a product image

**Group:** B. Board descriptions

**Needs:** B13

raze-base runs `serial-getty@ttyGS0`. With the security switch off, root logs in there with an empty password: that is
how Raze #2 was driven on 2026-11-22. It is right for the bench, and wrong for anything shipped: anyone with a USB cable
is root.

## Build

- A product says what it is: bench or bring-up, where an open console is allowed and named in its product.toml with the
  reason, or shipped, where it is not.
- `scripts/check-devices.sh` refuses a shipped product whose root has an empty or no password and that starts a
  getty or autologin on any tty. It reads the image's passwd and shadow and the enabled getty units from the planned
  root, not from comments.
- raze-base is classified with a reason. If it stays a bench product, the first shipped product's console is the
  owner's decision: locked root plus Orion's login helper (C52) for the recovery shell, or no getty.

## Proof

The check refuses a shipped product with the open console (self-test case), and passes raze-base as classified.
