# G10: the gate's grep guards fail on a match

Found by U2 (PR 119): a board name in a module comment printed a match, and the gate still said `gate passed`.

## Cause

The two guard steps ran `bash -c '! grep -rn … crates/*/*/src apps/*/src-tauri/src 2>/dev/null'`.
`apps/*/src-tauri/src` names no directory until the app lands. GNU grep returns 2 when an operand is missing, even
when it also matched, and `! 2` is 0. So both checks passed whatever the code held. Proof, on this machine:
a file holding `raze` plus a missing path gives grep status 2 and step status 0.

## Fix

`no_match` in scripts/gate.sh searches only directories that exist, and maps grep's status: 1 (nothing found)
passes, 0 (a match) fails with "found above: not allowed here", and 2 (an error) fails with "the check did not
run". A self-test step runs first, on a scratch dir: a match beside a missing glob must fail, and a clean tree must
pass.

## Checks

- The self-test passes.
- The current tree passes both guards. Run by hand before the fix with the missing path left out: no names, no ssh
  shell-outs, so no hidden violation was waiting on next.
- A planted `// raze` in crates/tools/next/src/main.rs fails the names step (status 1), then reverted.

## Audit: other guards that could pass on a tool error (coordinator's ask)

Searched scripts/ and .github/ for `! grep`, `|| true` and `2>/dev/null ||`. Each site:

- **Fixed: the five rule calls in check-devices.sh** (firmware, slot id, boot size, bring-up, erofs) ran
  `msg=$(rule) || true`. A rule prints its findings and returns 1 with them, so a rule that crashed with no output
  (an awk or grep error) passed. `rule_ran` now fails a non-zero status with nothing printed. Tested: status 2 with no
  output fails; status 1 with findings and status 0 with none do not add a failure.
- **Fixed: the per-unit state search** ran `grep -r … . 2>/dev/null | grep -v … || true`, so an unreadable file
  was skipped quietly. grep's status is now kept; 2 fails with "it did not run".
- **Already fail closed, unchanged:** every `! grep -q PATTERN FILE` that refuses on a missing line (an error is a
  refusal too); the `grep -qx … 2>/dev/null || { refuse }` checks; the kernel-fragment self-tests; the lock/validate
  checks.
- **Unchanged, with reason:** `$(grep -ho … || true)` value extractions in check-devices (135, 148, 375, 782) read
  files that find just listed; an empty value is then refused or reported as unused downstream, so an error does not
  pass. The `gaia --version … || true` lines compare the result to the pin and refuse a mismatch. The lock `diff
  … || true` only prints.

check-devices.sh: passed, self-check passed, after these changes.
