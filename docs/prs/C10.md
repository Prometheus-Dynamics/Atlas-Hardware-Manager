## Build

- Atlas reads the hello facts Lemnos publishes: `family`, `serial`, `model`, `version.slot`, `version.product`, `version.os`, `version.lemnos` and `offers` (space-separated contract ids, live), plus Orion's own `state`. A fact the node does not give is not reported. A malformed fact is refused with its reason (`refused.<fact>`) and is not reported; a serial that is not 8 to 32 lowercase hex digits never makes a key. Keys are made with `DeviceKey::board`/`DeviceKey::node`.
- `offers` grants the kinds of the contracts it names (`system.slots/1` grants slots and update). A node whose identity cannot be read but whose offers are present is Lemnos answering with no identity reported.
- A republish of the bridge's session (a fact came or went) is not a fault and not a changed identity: a read in that window keeps the identity and the Lemnos state the node had, for up to five seconds after its last read with the board key.
- The simulated node publishes the same facts: one text field `value`, history 2, and an absent fact is not published. Values changed by a test go out on the same session; a fact that appears or goes away republishes the node's session. `hello.version.slot` is written when the node starts and no confirm changes it. `hello.name` is gone: the name is a field of the hello document.

## Proof

Tests: each fact read; an absent fact is not reported; identity unreadable but offers present; a malformed serial refused; a value changing while connected; the republish blip is neither a fault nor a changed identity; the running slot unchanged by a confirm.
