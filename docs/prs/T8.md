# T8a: wall-clock tests on the sim clock

Scope (coordinator): the wall-clock tests that can be driven from the sim's clock on the current Orion pin
(671d29d6). Everything that needs the pin's liveness change is T8b, below, and monitor behaviour is unchanged here.

## What changed

1. **Topics hardware reader takes its clock** (`crates/board/topics/src/hardware.rs`). `Hardware::with_clock`
   takes an `atlas_session::Clock`; the reader's "now" is `origin + clock.now()`. `Hardware::with_grace` keeps the
   real clock, so the product behaviour is unchanged.
2. **`a_device_withdrawn_for_longer_than_the_grace_is_removed`** (topics `tests/hardware.rs`).
   - Wall-clock dependence: the grace was 300 ms of real time. Under load the removal and the "held" state
     depended on how far the machine had run, not on the grace.
   - Fix: the reader runs on a manual clock. The test waits for "held within the grace", advances the clock by
     grace + 1 ms, then waits for the removal.
3. **`a_board_that_refuses_describe_shows_its_devices_as_not_available_until_a_refresh`** (topics).
   - Wall-clock dependence: the connect-time ask and the generation topic's first sample race. The count of asks
     is 1 or 2 depending on which comes first. The test already allowed both, and the property it checks is
     "no ask on a timer".
   - Fix: the test now waits for the vane's first generation sample as an event before it takes the count. The
     accepted outcome set (1 or 2) is unchanged and stated in the test.

## Classified, kept as they are

These are event waits. Each has a `DEADLINE` or a poll only as a safety net, and the event they wait on does not
depend on how fast the machine runs.

| Site | Wait | Class | Why kept |
|---|---|---|---|
| topics `tests/hardware.rs` `read_until`, the log loop, `connected` | poll 20/50 ms to `DEADLINE` 120 s | safety net around an event (a snapshot changing) | the event is the node's reading, which arrives on the session, not on a clock |
| tools/next `tests/common` `until` (60 s, `DEADLINE` from atlas_sim_node) and `play_board` | poll 5 ms | safety net around sim model events | the events are the sim's own state changes (install, trial, list). The sim's progress is paced by its tick (20 ms real), so the bound can only fire on a broken run; the loaded proof never reached it |
| files `tests/push.rs` `progress_where`, `job_where`, `connected` | `DEADLINE` 120 s | safety net around a progress event | the push's progress is an event; the 120 s bound is the only clock |

## Fixed earlier on this branch (not part of the list above)

## T8b, on the Orion pin (not in this PR)

- `crates/board/session/tests/session.rs`: `a_call_on_a_node_that_is_gone_says_so_at_once` (elapsed < 1 s) and
  `a_call_that_is_not_answered_in_the_call_wait_is_gone_and_the_session_survives` (waited ≥ call wait, < 4 s). Both
  assert on real elapsed time of the call wait, which is the monitor's `CALL_WAIT` (`monitor.rs:60`, `:509`).
- `crates/board/session/tests/session.rs` `a_queued_call_whose_caller_gave_up_is_not_started_later` (300 ms
  call wait): the same call-wait timer.
- The connect-time reply deadline `CONNECT_TIMEOUT` reused as a per-reply deadline (`monitor.rs:57`, `:763`):
  the liveness change (Reply::Alive with per-kind ceilings) lands with the Orion pin.
- The sim case "no welcome after a link bounce": needs the pin's liveness behaviour.

## Proof

- Topics hardware tests (9): 20 consecutive runs of the whole topics `hardware` binary under the 30-process CPU
  load (cores 6-31), run from the systemd user unit `atlas-T8-loop2` (with `LimitNOFILE=1048576` and the env set).
  Result: passed 20 of 20. The first loop (`atlas-T8-loop`) stopped at run 1 on the grace test: the test
  waited for "held" when only some devices were unlisted; the advance then took them as last seen. The fix is
  in the test: every device must be unlisted before the clock moves. That run was a finding, and it was fixed,
  not rerun away.
- Gate: `scripts/gate.sh` with `ATLAS_SCRATCH_ROOT=/mnt/ssd-samsung/sc-T8` and the T8 target dir, run as the
  systemd unit `atlas-T8-gate2`. Result: rc=0 (every step).
