## Step 3: the `[generate]` block (`devices/components/raze-lemnos-board/component.toml`)

```toml
[sources.root]
image = "docker.io/library/rust:1.99-slim"
platform = "host"

[generate]
description = "lemnos"
tool = { source = "lemnos", package = "lemnos-ctl" }
args = [
  "tree", "--socs", "@source@/socs", "@description@",
  "-o", "@out@/overlay.dts",
  "--modprobe", "@out@/modprobe.conf",
  "--cmdline", "@out@/cmdline.words",
]
outputs = ["overlay.dts", "modprobe.conf", "cmdline.words"]
```

- The tool is `lemnos-ctl`, built from the component's own `lemnos` source (`[sources.lemnos]`, at `d6b9361d`) for the build machine's architecture, with the `root` image's C library (Gaia #100). The `root` image is the same one `lemnos-ctl`'s component uses. Its digest is in the product lock: `[source."raze-lemnos-board.root"]`, `digest = "sha256:f6c4a35d…dd02d7"`.
- `--boot` is not passed. Gaia has no key for config.txt lines; the boot lines are Lemnos's own later steps (`tree --boot-dir`, and at L2 the boot-partition step).
- The modprobe output is wired, see below. The overlay and command line are declared with no consumer at this rev.

### Installs replaced by generated files

None of the Raze's hand-written installs is a copy of a file `lemnos-ctl tree` writes at this Lemnos lock. The udev rule is not generated at `d6b9361d` (no `--udev`). The i2c module load is not a `tree` output. So no hand-written file is removed.

What was added instead: `[[install]] from = { generated = "modprobe.conf" }` to `/etc/modprobe.d/lemnos.conf`. Before this PR the Raze image had **no modprobe.d fragment for Lemnos**: the component said "not kept here" and nothing generated it. The path is the one Lemnos documents (`testing/board-runs/Q2c.md:68`, "Install `lemnos.conf` in `/etc/modprobe.d/`"). `lemnos.ko` is not built by this kernel yet, so the options name a module that does not load.

### Outputs with no consumer at 7177d72

- **`overlay.dts` (`-o`)**: Gaia builds a board's kernel overlays only by name from the kernel's device tree directory (`kernel.overlays`, `crates/core/graph/src/os.rs:197`). No step compiles a generated `.dts` (`dtc -@`) and places it. Declared, not installed, not hand-copied. The Raze's `overlay/README.txt` still says the overlay is not committed.
- **`cmdline.words` (`--cmdline`)**: Gaia names no kernel command-line key at this rev. The Raze's command line is the firmware's `cmdline.txt`, on a boot partition the slot recipe does not produce. Declared, not installed.

Both gain consumers through `[generate.provides]` in later Gaia revs (INPUTS.md, "Gaia's plan for the generated outputs"). That key is **not** at `7177d72`, so it is not written here. Revs come from the coordinator one by one.
