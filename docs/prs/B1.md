## Build

- `devices/families`, `devices/boards`, `devices/components`, `devices/products`, `devices/gaia.lock`, and app data beside each board. `scripts/check-devices.sh` checks every file with Gaia `next` at the Gaia commit named in the lock, and is run by the gate. Today the only check is `gaia plan`, which needs a `gaia.lock` and every tool a recipe names on the path; `gaia validate` (description-level checks, no lock or tools) is being added to Gaia, and the script uses it when it exists and plan otherwise.
- Read Gaia `next` `docs/design.md` and `examples/boards`, `examples/products`, `examples/packages`.
- Format points from Gaia's F8: a product has `[sources.<name>]` and an image takes `os = { provider = "buildroot", source = ..., fragments = [...] }`; `[bootloader.blobs]` keys are the make variables U-Boot reads (`ROCKCHIP_TPL`), capitals, digits and `_` only; `kernel.defconfig = "defconfig"` is the architecture default; `kernel.overlays` is refused for an OS build for now; the slot recipe is `slot`; `@here@` in a fragment file is that file's directory. Gaia derives arch, CPU, kernel, U-Boot and TF-A sources, defconfigs, fragments, DTS and blobs from the board; toolchain, packages and output format go in the image's fragments.
