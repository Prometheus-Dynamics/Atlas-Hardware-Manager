- Windows and macOS: implemented, type-checked, **not run**. The write is refused on both until the host test passes and the proof constant is flipped in one place (`crates/flash/disk/src/platform.rs`: `WINDOWS_PROOF`, `MACOS_PROOF`).

## What exists on Linux (before this PR)

`crates/flash/disk/src/linux.rs` and `disk.rs`:

- **Listing.** `/sys/block` for whole disks (skips loop, ram, zram, dm, md, sr, fd, nbd); size from `size`; vendor, model, serial from `device/`; `removable` from `removable`; USB from the sysfs path (`usbN`), with the USB port (`1-4.2`) taken from the deepest port component. Mount points from `/proc/self/mountinfo` on the disk, its partitions and any device-mapper holders above them; swap from `/proc/swaps`. A disk is `system` when a mount is `/`, `/boot`, `/efi`, `/usr`, `/var`, `/home` (or below), or a swap device is on it.
- **Refusals** (`check_target`): system or boot disk; not removable (even over USB); no media (size 0); larger than 2 TiB; size changed since choice.
- **Unmount.** Every mount of the disk and its partitions, deepest first (`umount`), before the open. A system mount never gets there.
- **Open.** `O_RDWR | O_EXCL` on `/dev/sdX` (an exclusive open fails while anything else holds the disk).
- **Write.** Buffered `write_all_at`, 16 MiB segments (`ResumePolicy`), each segment `sync_data` then read back with `posix_fadvise(DONTNEED)` and compared. A drop (write, flush or read error) reattaches: find the disk by USB port (else path), check it again as new, reopen, resend the segment from memory, with backoff capped at 5 s. A journal (`image.journal`) lets a rerun skip proven bytes; they are still read and compared.
- **Image.** xz: one image stream, optionally one signature record stream (`atlas_xzdec`); the writer decodes the image stream only, so the record never reaches the disk. SHA-256 of the image optional, checked before any write. Zip refused.
- **Privilege.** The helper (`crates/tools/helper`, `atlas-helper write`) runs with rights, takes JSON arguments only (device must match a whole-disk shape, no shell), finds the disk in a fresh listing, and writes progress and the result as JSON lines.
- **Non-Linux before this PR.** A stub: every call returned `DiskError::Unsupported("... only available on Linux so far")`. Nothing could pass for a write.

## Facts per system, with sources

Each fact is from the document named. Where a page could not be fetched, the fact is marked as not read.

### Windows (Microsoft Learn; the archived Windows hardware pages)

1. **Raw disk path.** `\\.\PhysicalDriveN`, numbered from 0. Volume `\\.\C:`, or `\\?\Volume{GUID}`. Source: *CreateFile function* (fileapi.h), section "Physical Disks and Volumes"; the examples table of `\\.\PhysicalDrive0`.
2. **Administrator.** Opening a physical drive or a volume for direct access requires administrative privileges; a volume needs `FILE_SHARE_WRITE`. Source: *CreateFile function*, "Physical Disks and Volumes", the list of requirements.
3. **Volume to disk.** `IOCTL_VOLUME_GET_VOLUME_DISK_EXTENTS` on a volume handle returns the disk number and offset of each extent; a volume can span disks. Source: *CreateFile function*, "Physical Disks and Volumes".
4. **Lock and dismount.** `FSCTL_LOCK_VOLUME` locks a volume if it is not in use: it fails if any file on the volume is open. The system flushes cached data first. A locked volume is treated as dismounted by NTFS. The lock lasts until the handle closes or `FSCTL_UNLOCK_VOLUME`. A system volume or a volume with a page file cannot be locked. `FSCTL_DISMOUNT_VOLUME` does not check for open files, and without a lock a dismounted volume may be remounted by any process. Source: *FSCTL_LOCK_VOLUME* (winioctl.h), Remarks.
5. **The write rule.** Since Windows Vista, the storage stack lets a write through a disk handle reach a mounted volume only when the volume is explicitly locked, or not mounted, or has no file system. Sectors outside any volume (partition tables, metadata) are always reachable. Source: *Restricted Direct Disk Access and Volume Access in Windows* (Windows 10 hardware dev archive, `dn653576(v=vs.85)`), section "Details of write restrictions to the file system and to the storage stack", and its reference to KB 942448. The current learn.microsoft.com copy of this page returned 404 when fetched; the archived copy was read.
6. **Alignment.** With `FILE_FLAG_NO_BUFFERING`, every transfer size and file offset is a multiple of the volume's sector size, and buffer addresses should be sector-aligned. The physical sector size comes from `IOCTL_STORAGE_QUERY_PROPERTY` (`STORAGE_ACCESS_ALIGNMENT_DESCRIPTOR`, `BytesPerPhysicalSector`). Source: *File Buffering*, "Alignment and File Access Requirements". The implementation uses buffered write-through I/O with whole-sector transfers; buffer alignment is not used. Whether a raw physical drive accepts buffered sector-multiple I/O without `NO_BUFFERING` is a host-test question (see the host test step 9).
7. **Flush and re-read.** `FlushFileBuffers` flushes; `IOCTL_DISK_UPDATE_PROPERTIES` "invalidates the cached partition table and re-enumerates the device", and needs no volume lock. Source: *IOCTL_DISK_UPDATE_PROPERTIES* (winioctl.h), Description and Remarks.
8. **Identity and kind.** `IOCTL_STORAGE_QUERY_PROPERTY` with `StorageDeviceProperty` returns `STORAGE_DEVICE_DESCRIPTOR`: `RemovableMedia`, `BusType`, and the vendor, product and serial strings at their offsets. `BusTypeUsb` is 7 in `STORAGE_BUS_TYPE`. Source: *STORAGE_DEVICE_DESCRIPTOR* and *STORAGE_BUS_TYPE* (winioctl.h). A card reader that reports `RemovableMedia` false is refused by the same rule as any fixed disk; how common that is is a host-test question.
9. **Disk with no volumes.** Sectors outside any volume are reachable through a disk handle without locking (the storage driver's condition 1 in source 5). The write goes on with no lock step.
10. **Elevation.** A non-elevated app cannot open the raw disk. `ShellExecuteEx` with the `runas` verb starts a program elevated: User Account Control asks the user for consent. Source: *Launching Applications (ShellExecute, ShellExecuteEx, SHELLEXECUTEINFO)*, "Object Verbs" (the `runas` row). The app's launcher is not in this PR (see open points).
11. **Not read.** `IOCTL_DISK_GET_DRIVE_GEOMETRY_EX`, `IOCTL_STORAGE_EJECT_MEDIA`, `FindFirstVolumeW` and `GetVolumePathNamesForVolumeNameW` reference pages were not fetched; their names and layouts come from the `windows-sys` 0.61.2 bindings and are checked by the type-check, not by a document read here.

### macOS (Apple man pages and developer forums; developer.apple.com pages largely unavailable)

1. **Nodes.** `/dev/diskN` is the block device; `/dev/rdiskN` the raw character device used for whole-sector writes. Source: diskutil(8) and the `diskutil` verbs (below); the raw-device usage in the Apple Developer Forums thread (below). The distinction is well known; the exact Apple wording was not fetched.
2. **Unmount all volumes.** `diskutil unmountDisk` (given "a disk containing a partition map, unmount all of its volumes"; `force` force-unmounts "less kind to any open files"). Source: diskutil(8) manpage (keith.github.io mirror of Apple's `xcode-man-pages`), VERBS: unmountDisk. The DiskArbitration equivalent is `DADiskUnmount` with `kDADiskUnmountOptionWhole` (value `0x1` in the DiskArbitration header, read through a search excerpt; the developer.apple.com page returned 404). Not used here: `diskutil` is the smaller dependency.
3. **Eject.** `diskutil eject` ("Eject a disk"). Same source.
4. **Listing.** `diskutil list -plist` (all disks and partitions, with `MountPoint`s in the tree) and `diskutil info -plist` per disk (keys read: `WholeDisk`, `VirtualOrPhysical`, `RemovableMedia`, `BusProtocol`, `TotalSize`, `MediaName`, `DeviceBlockSize`). The key names are from the `diskutil info` output the author knows; the host test confirms them. DiskArbitration keys (`DADiskDescriptionMediaRemovableKey`, `…DeviceInternalKey`, `…MediaWholeKey`, `…MediaBlockSizeKey`) are the in-process alternative; their names were confirmed by search excerpt only.
5. **Authorisation.** `authopen` provides "authorization-based file opening services": it checks authorisation for the path, opens it, and sends the open descriptor back over a pipe with `-stdoutpipe`; `-extauth` takes an authorisation the caller made. Source: authopen(1) manpage (keith.github.io mirror), DESCRIPTION and the `-stdoutpipe`/`-extauth` options. The `-o` open-flags argument used here (`-o 2`, read-write) is from the author's reading of the same manpage family and is UNPROVEN until the host test runs it.
6. **Permission errors and prompts.** A Developer Forums thread (developer.apple.com/forums/thread/777577) reports `errno 13` writing `/dev/rdisk99`; an Apple DTS engineer's reply says errno 13 is ordinary BSD permission, not a sandbox (EPERM) or TCC error. The reply suggests `AuthorizationExecuteWithPrivileges` for a personal app and an `SMAppService` daemon for wide distribution. The thread's read/write prompt observations ("Access Removable Media" / "Full Disk Access") are the poster's, not confirmed by Apple. A Privacy Guides news item (2026-10-06) reports Apple tightening Full Disk Access; Apple's own post was not read. Whether a removable-volume prompt appears in this flow is a host-test question.
7. **Caching and flush.** `fcntl(2)` (keith.github.io mirror): `F_NOCACHE` "turns data caching off/on"; `F_FULLFSYNC` "does the same thing as fsync(2) then asks the drive to flush all buffered data to the permanent storage device"; it is implemented on HFS, FAT, UDF and APFS. Used: `F_NOCACHE` on open, `F_FULLFSYNC` as the flush.
8. **Block size.** Raw-device writes must be whole blocks of the device's block size. No Apple page was read that states this; the implementation aligns to `DeviceBlockSize` (512 when absent) and the host test checks it.

## What is implemented

- **The seam** (`crates/flash/disk/src/platform.rs`): `trait Platform: DiskSource` with `name`, `proof`, `may_write` (elevation), `prepare` (unmount or lock; returns a guard that releases on drop), `open` (raw device), `finish` (flush, re-read, eject). `RawDisk` is the positioned read/write/sync the pipeline uses.
- **The shared pipeline** (`device.rs`, `writer.rs`, `sector.rs`): `write_disk(platform, chosen, ack, request, progress, cancel)`. In order: the proof gate, elevation, a fresh listing (the chosen disk must be there, same size, same serial, model and USB port where both records have them, not a system disk, removable, within the size bound), the image check (hash, format, fits) before any volume is touched, then `prepare`, `open`, the segments with verify and resume, and `finish`. A failed write is not finished: only the raw device and the guard are dropped. `Device` is the `Target` that reattaches through the same checks. `sector::Sectored` makes whole-sector I/O for raw devices: a final part inside a sector is written by reading that sector and rewriting it with the image's bytes changed, the bytes after the image unchanged.
- **Linux** (`linux.rs`): `LinuxPlatform` holds the code that was inline (unmount, exclusive open, `sync_data`); behaviour unchanged, its tests pass unchanged.
- **Windows** (`windows.rs`, `#[cfg(windows)]`): listing with `IOCTL_STORAGE_QUERY_PROPERTY`, `IOCTL_DISK_GET_DRIVE_GEOMETRY_EX` (size and sector), volumes by `FindFirstVolumeW`/`FindNextVolumeW` and `IOCTL_VOLUME_GET_VOLUME_DISK_EXTENTS`, mounts by `GetVolumePathNamesForVolumeNameW`; system = a mount at the `SystemDrive` root; `prepare` locks then dismounts every volume of the disk (`FSCTL_LOCK_VOLUME`, `FSCTL_DISMOUNT_VOLUME`), a failure is `Busy`; the raw device by `std::fs` with `FILE_FLAG_WRITE_THROUGH` and `seek_write`/`seek_read` looping, through `Sectored`; `finish` flushes, `IOCTL_DISK_UPDATE_PROPERTIES`, `IOCTL_STORAGE_EJECT_MEDIA`; `may_write` checks the process token's `TokenElevation`. Marked UNPROVEN.
- **macOS** (`macos.rs`, `#[cfg(target_os = "macos")]`): listing and eject with `diskutil` (`plist` parsing), whole physical disks only (`WholeDisk`, `VirtualOrPhysical`); system = a mount at `/`, a system path, or under `/System/Volumes/`; `prepare` = `diskutil unmountDisk`; `open` = `authopen -stdoutpipe -o 2 /dev/rdiskN`, the descriptor received with `recvmsg` (SCM_RIGHTS) over a socket pair, then `F_NOCACHE`, through `Sectored`; `finish` = `F_FULLFSYNC`, drop, `diskutil eject`. Marked UNPROVEN.
- **Unsupported systems** (`unsupported.rs`): every call refuses, as before.
- **The proof** (`platform.rs`): `LINUX_PROOF = Proven`, `WINDOWS_PROOF = Unproven`, `MACOS_PROOF = Unproven`, read by `host_proof()`. `host_acknowledgement()` is `Given` only on a proven system. The gate refuses `Unproven` + `Withheld` before anything is listed, with a message that names the host test and this file.
- **The helper** (`crates/tools/helper`): `write` goes through `write_disk` with the host platform; new `--expected-serial`, `--allow-large`; `atlas-helper list` (new) prints the host, its proof and acknowledgement, and each disk with its verdict (`would be written` or `refused: ...`). `list` reads only.
- **Safety rules, tested with a fake platform** (`tests/seam.rs`, 13 tests): order (`may_write`, `list`, `prepare`, `open`, writes, read-back, `finish` after the last flush, then the raw device and the volumes released); unproven refused before anything; unproven written with the acknowledgement; elevation refused before any prepare; system disk refused; a changed serial or size refused; a vanished disk refused with its own message and no prepare; a disk above 256 GB needs a second choice; a failed open takes nothing; a cancelled write is not finished and writes nothing after the cancel; nothing written past the image's size and the signature record never reaches the target (an xz file with a record stream); a drop reattaches and goes on on the same disk; a disk that vanishes during a drop is reported by name until cancelled; a failed finish says the image is written and verified. `sector.rs` has 5 tests of the tail rule and alignment on an in-memory disk.
- **Large disks.** `LARGE_DISK_BYTES = 256_000_000_000`. Above it a write needs `allow_large` (the helper's `--allow-large`, which the app passes only after a second, explicit choice). Why 256 GB: a first-flash card is smaller; a larger removable disk is more often a drive that holds data.
- **Size bound.** `MAX_CARD_BYTES` (2 TiB, SDXC) is the hard refusal, unchanged.

## What is unproven (not run on Windows or macOS)

- Everything in `windows.rs` and `macos.rs`. Both are type-checked (see below), not run.
- Windows: lock-then-dismount ordering on a busy volume; buffered whole-sector I/O on a physical drive (vs `NO_BUFFERING`); `IOCTL_STORAGE_EJECT_MEDIA` on a physical-drive handle; `TokenElevation` on the target machines; whether a common card reader reports `RemovableMedia`.
- macOS: the `authopen` arguments and the descriptor return; whether the authorisation prompt is the only prompt; the `diskutil info` key names and the `DeviceBlockSize` key; `F_FULLFSYNC` on the card; whether unmount refuses a busy volume.

## Left out, and why

- **The app's elevation launcher** (`ShellExecuteEx` with `runas`, and the wait for the progress file): it belongs to the app (apps/desktop, not in this PR). The helper checks `may_write` and refuses cleanly if not elevated.
- **Windows device serial and USB port** (`usb_port` is `None` on Windows; the `same_disk` check then uses serial and model). Adding the SetupAPI port lookup is a follow-up after the host test shows which fields a reader gives.
- **DiskArbitration.** `diskutil` is used. A native DiskArbitration/IOKit path would avoid the subprocess and the `plist` dependency; it is not needed for the host test.
- **Partition table re-read on Linux.** Not added; Linux behaviour is unchanged.
- **The journal on Windows and macOS** uses the same file as Linux (`image.journal`) and the same identity rule (`target.identity()`); not run on those systems.
