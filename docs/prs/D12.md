# D12: Find a board's Orion link over USB by its interface string

**Group:** D. Flashing

**Wave:** 4

**Needs:** D1, A8

**Runs:** cloud

Read `AGENTS.md` and `docs/design.md` first.

## Creates

- `crates/flash/usb (edit)`

## Read on dev

- nothing

## Build

- A running or freshly loaded board's USB gadget is one configuration with three functions: a vendor interface (class 0xFF, two bulk endpoints, interface string `orion-link`) that is Orion's link, NCM for the network, and one ACM console. The computer finds Orion's link by the interface string, never by a ttyACM number.
- `atlas-usb` lists a device's interfaces with their class and string, and opens and claims a vendor interface chosen by its string, on Linux, Windows and macOS. The string comes from the caller as data. The simulated bus does the same.
- Say what each host needs for the interface to be claimable (a udev rule on Linux, WinUSB binding on Windows 11, nothing or an entitlement on macOS), and what the NCM network needs on each. Don't add an installer step here; list it for F9.

## Proof

Tests on the simulated bus: a device with the three functions is found by string; a device without it is not; two boards plugged in are told apart.
