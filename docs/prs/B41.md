# B41: raze-base drops D-Bus and four unused systemd daemons

Data and one script: `devices/products/raze-base/os/raze.fragment`, the new `devices/products/raze-base/os/post-build.sh`
(mode 755), and this file. Nothing else is touched. No cargo build, no gate run locally (the brief's rule; CI's `gate`
check is the gate).

## The approval and its conditions

Approved by the coordinator on the brief for this PR. The conditions the brief set, and what was done with each:

1. Remove dbus with a FIXED list, derived from the extracted root. Done: `DBUS_REQUIRED` and `DBUS_OPTIONAL` in
   post-build.sh (below).
2. FAIL the build if a listed path is missing. Done: the required paths are checked before anything is removed, and
   every missing one is named.
3. FAIL if an ELF left under the target has a NEEDED libdbus-1. Done, with the host binutils `readelf` (reason in the
   script: Buildroot's `TARGET_READELF` is a make variable, not exported to post-build scripts).
4. FAIL if an enabled unit has `Type=dbus`. Done, with ONE change to the brief, stated under "Where this PR departs
   from the brief" below: an enabled unit with only `BusName=` is a note, not a failure.
5. Four systemd options off (networkd, resolved, timesyncd, hostnamed). Done for resolved, timesyncd and hostnamed.
   NOT done for networkd: it stays on. See "Where this PR departs from the brief".
6. Timedated: Buildroot defaults it to y. Set off explicitly as well (same as the other three).
7. `keep_setid`: stays empty, unchanged. `product.toml` has no `keep_setid` comment, so there was none to update.

## Where this PR departs from the brief

- **networkd stays on.** The brief asked for `BR2_PACKAGE_SYSTEMD_NETWORKD` off, with the reason "the address comes from
  lemnos0-address.service; etc/systemd/network is empty". That reason does not hold on this tree. `lemnos0-address`
  (devices/components/raze-base-files/files/lemnos0-address) only WRITES `/run/systemd/network/10-lemnos0.network`;
  networkd is what reads it, and that file carries the `DHCPServer=yes` that serves DHCP to the host (the coordinator's
  ruling of 2026-11-14, in the fragment). Orion's peer listen address (`ORION_PEER_LISTEN`) is the same board address.
  `raze-base-files/component.toml` enables `systemd-networkd.service`. Turning networkd off would take away the board's
  address, its DHCP server and the peer address. So it stays on. The coordinator must confirm this, or the ruling must
  change first.
- **The BusName rule.** The brief's check (4) says "Type=dbus or BusName=, and enabled". networkd is enabled and has
  `BusName=org.freedesktop.network1` with `Type=notify-reload`: it starts without the bus. The literal rule would refuse
  the build on a unit that has to stay. So the check fails on an enabled `Type=dbus` unit (the one that cannot start
  without the bus), and lists an enabled `BusName=`-only unit as a NOTE in the build log. The coordinator must accept this.
- **Timedated** is set off in addition to the three the brief named (it is one of the four bus daemons, and Buildroot
  defaults it to y).

## The evidence

From Gaia's raze-base root of Atlas f8e7a2c6, extracted at the scratch path (read only; the self-test ran on copies):

- libdbus-1 is linked only by dbus's own tools (the brief's scan). The self-test's pass case checks it again on the
  root: after the list is removed, no ELF under the root needs libdbus-1.
- No Lemnos or Orion binary uses the bus.
- BusName= appears only on networkd, resolved, timesyncd, hostnamed and timedated. None of them had a wants link in the
  extracted root, so none was enabled there. Only networkd is enabled by this tree's component (above).
- Enabled dbus links: `multi-user.target.wants/dbus.service`, `sockets.target.wants/dbus.socket`, and the user
  `sockets.target.wants/dbus.socket`.
- `hostnamed.socket` is enabled in the extracted root. Its option is off in this PR, so the socket goes with it.
- `messagebus` is not in the root's `etc/passwd` or `etc/group`: no account to remove.
- Buildroot: `package/systemd/Config.in` has `select BR2_PACKAGE_DBUS if !BR2_PACKAGE_DBUS_BROKER`, so dbus cannot
  be turned off by a fragment line. The option names checked in the Buildroot tree (`/mnt/ssd-samsung/gaia/work/D3/br-src`):
  `BR2_PACKAGE_SYSTEMD_RESOLVED`, `_TIMESYNCD`, `_HOSTNAMED`, `_TIMEDATED`, `_NETWORKD`. All five default to y there.
- Buildroot calls the post-build script as `$(s) $(TARGET_DIR)` (Makefile, the ROOTFS_POST_BUILD_SCRIPT foreach), so the
  file must be executable: it is 755 in git.

## The fixed list

Required (must exist; removed; a directory with its whole tree):

```
etc/dbus-1
usr/bin/dbus-cleanup-sockets   usr/bin/dbus-daemon       usr/bin/dbus-launch
usr/bin/dbus-monitor           usr/bin/dbus-run-session  usr/bin/dbus-send
usr/bin/dbus-test-tool         usr/bin/dbus-update-activation-environment   usr/bin/dbus-uuidgen
usr/libexec/dbus-daemon-launch-helper
usr/lib/libdbus-1.so   usr/lib/libdbus-1.so.3   usr/lib/libdbus-1.so.3.38.3
usr/lib/systemd/system/dbus.service        usr/lib/systemd/system/dbus.socket
usr/lib/systemd/system/multi-user.target.wants/dbus.service
usr/lib/systemd/system/sockets.target.wants/dbus.socket
usr/lib/systemd/user/dbus.service          usr/lib/systemd/user/dbus.socket
usr/lib/systemd/user/sockets.target.wants/dbus.socket
usr/lib/sysusers.d/dbus.conf               usr/lib/tmpfiles.d/dbus.conf
usr/share/dbus-1          (the bus policy and activation files, systemd's included: system.d/, system-services/, services/)
usr/share/xml/dbus-1
var/lib/dbus              (machine-id is a symlink to /etc/machine-id)
```

Optional (removed if present; present only when a daemon's option is on):

```
run/dbus
usr/lib/systemd/system/dbus-org.freedesktop.hostname1.service
usr/lib/systemd/system/dbus-org.freedesktop.timedate1.service
```

Systemd's own files are not on the list: libsystemd and systemd-stdio-bridge stay. Two things go that are systemd's:
the bus activation and policy files under `usr/share/dbus-1` (for systemd1, hostname1, network1, resolve1, timedate1,
timesync1), which only a bus can use, and the dbus-named alias units above.

After the removal the script also fails if any path containing `dbus` is left (`find . -path '*dbus*'`).

Apparent size of the list on the extracted root (measured with `du -sb --apparent-size` per path): 834,995 bytes in all;
786,824 of that is the dbus binaries, the libexec helper and libdbus-1 (about 768 KiB). The bus policy files and the rest
are the remainder.

## What is NOT proven

- **The first board boot's journal must show nothing asking for the bus.** Nothing here runs a boot. The journal of the
  first boot of a slot built with this fragment must be read: no unit should fail for a missing bus, and no
  `org.freedesktop.*` name should be requested.
- That the image builds. Only `check-config-only` (the configuration resolves) and the self-test on the extracted root
  were run. The build itself is for CI's `gate` and Gaia's next real build.
- That networkd runs without dbus on the board (it is `Type=notify-reload`, so it should, but it is not seen).
- That the removed daemons are not needed by any path not in the scans (the scans covered the built root, the components'
  files, the Lemnos and Orion packages at origin/next).

## Doubts (read these first)

1. networkd stays on, against the brief. Needs the coordinator's confirmation.
2. The BusName-only rule, relaxed to a note for enabled units. Needs the coordinator's confirmation.
3. `hostnamed.socket` in the extracted root is enabled. The option being off removes it in the real build. The
   post-build check does not look at sockets that activate a dbus-typed service, so a future re-enable of hostnamed
   would not be caught by check (4). Adding that is a one-line rule, but it would fail the self-test on the extracted
   root as it is now.
4. The script is not wired into `scripts/check-devices.sh`. That script's self-checks use fixtures in
   `devices/tests/fixtures`; the extracted root is a Gaia build artifact (72 MB) and is not in the repo. The post-build
   script carries its own `--self-test`, run as shown above.
5. The optional list is not checked at build time: a missing optional path is not an error, by design.
