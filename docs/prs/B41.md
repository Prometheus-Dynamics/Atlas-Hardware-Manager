# B41: raze-base drops D-Bus, four unused systemd daemons, and the network-online wait

Data and one script: `devices/products/raze-base/os/raze.fragment`, the new `devices/products/raze-base/os/post-build.sh`
(mode 755), and this file. Nothing else is touched. No cargo build and no gate run locally (the brief's rule; CI's `gate`
check is the gate).

## The approval and its conditions

Approved by the coordinator on the brief. The coordinator then OK'd the two departures below, and asked for two additions
(the wait-online mask and the dangling-socket rule). Each is in this PR as its own commit.

1. Remove dbus with a FIXED list, derived from the extracted root. `DBUS_REQUIRED` and `DBUS_OPTIONAL` in post-build.sh.
2. FAIL if a listed path is missing. The required paths are checked before anything is removed; every missing one is named.
3. FAIL if an ELF left under the target has a NEEDED libdbus-1. The host binutils `readelf` is used (reason in the script:
   Buildroot's `TARGET_READELF` is a make variable, not exported to post-build scripts).
4. FAIL if an enabled unit is `Type=dbus`. Coordinator's OK: an enabled `BusName=`-only unit is a NOTE, not a failure.
5. Four systemd options off: resolved, timesyncd, hostnamed, and timedated (Buildroot defaults all four to y). networkd stays
   on. Coordinator's OK.
6. `keep_setid` stays empty. `product.toml` has no `keep_setid` comment, so there was none to update.
7. (addition 1) The network-online wait is off: the wait-online unit is masked. See "The network-online wait".
8. (addition 2) FAIL on an enabled socket whose service is missing or removed. See "The socket rule".

## Where this PR departs from the brief

- **networkd stays on** (coordinator's OK). `lemnos0-address` writes `/run/systemd/network/10-lemnos0.network`, which
  networkd reads; that file carries the Raze's DHCP server, and Orion's peer address is the board address it sets.
  Without networkd there is no lemnos0 address and no DHCP server.
- **BusName-only units are notes** (coordinator's OK). networkd is `Type=notify-reload` with an advertised `BusName=`.
- **Timedated is also off**, with the three the brief named.
- **The socket rule has a rule the brief did not state**: an enabled socket that starts one of the four daemons this image
  turns off fails (`OFF_SERVICES`). The brief's "service missing or removed" does not fail the raw extracted root, because
  `systemd-hostnamed.service` is present in it. The coordinator asked that the raw root fail on hostnamed.socket, so this
  rule is what makes it fail. Confirm, or the rule goes and the root needs another test.
- **A socket with no `Service=` and no same-named service is a NOTE, not a failure.** Three enabled sockets of the stock
  root have no service file and no `Service=` line: `systemd-ask-password.socket`, `systemd-creds.socket` and
  `systemd-factory-reset.socket`. A literal "service missing" rule would fail the build on them. An explicit `Service=`
  naming a missing or masked unit does fail.

## The network-online wait

### Which units reference network-online.target

Searched the extracted root's `usr/lib/systemd` and `etc/systemd` (with drop-in directories) and `devices/components`,
`devices/products/raze-base`, `devices/families/bcm2712`:

| unit | line | what it says |
|---|---|---|
| `systemd-networkd-wait-online.service` | 18, 26 | `Before=network-online.target shutdown.target`, `WantedBy=network-online.target` |
| `systemd-networkd-wait-online@.service` | 18, 26 | the same, instanced (not enabled by anything here) |
| `systemd-networkd.service` | 68, 69 | comments only: it names the target, and orders on nothing that waits for it |

No other unit orders, requires or wants network-online.target. No drop-in directory exists for networkd or wait-online.
Nothing in devices/components (Lemnos, Orion, raze-base-files) names network-online or wait-online.

### How this image applies presets

- Buildroot's `package/systemd/systemd.mk` (SYSTEMD_PRESET_ALL) runs `systemctl --root=TARGET_DIR preset-all`, as a
  ROOTFS_PRE_CMD_HOOK.
- Order (Buildroot Makefile and `fs/common.mk`): the post-build script runs in the target-finalize step. The pre-cmd hooks
  run later, inside the rootfs fakeroot script, after mkusers and makedevs. So a file this script writes is in place when
  presets run. The presets' links are not visible to this script, which is why the socket check below reads the preset
  files and does not see their results.
- The preset files in the root: `80-buildroot.preset` (no lines; comments only), `80-orion.preset` (`enable orion-comm.service`,
  `enable orion-node.service`), and `90-systemd.preset` (line 31: `enable systemd-networkd-wait-online.service`; line 30:
  `enable systemd-networkd.service`).

### Why not a disable preset, and why not a drop-in (tested)

Host systemd 259, `systemctl --root=<copy> preset-all`, on copies of the extracted root:

| copy | what it adds | wait-online linked? | networkd linked? |
|---|---|---|---|
| plain | nothing | yes, `etc/systemd/system/network-online.target.wants/systemd-networkd-wait-online.service` | yes |
| disable | `10-raze.preset`: `disable systemd-networkd-wait-online.service` | **yes** (still) | yes |
| drop-in | `systemd-networkd.service.d/10-raze-no-wait-online.conf` with `[Install] Also=` | **yes** (still) | yes |
| mask | `etc/systemd/system/systemd-networkd-wait-online.service -> /dev/null` | **no** | yes |

Why the disable line fails: networkd's `[Install]` carries `Also=systemd-networkd-wait-online.service` (line 70 of the
unit), so enabling networkd enables wait-online, whatever the preset says. Why the drop-in fails: systemd reads `[Install]`
from the unit file itself, not from drop-ins (the drop-in's empty `Also=` had no effect). A mask is honoured: preset-all
prints `Unit ... is masked, ignoring` and links nothing for it.

### The method: a mask in post-build.sh

`ln -sfn /dev/null "$T/etc/systemd/system/systemd-networkd-wait-online.service"` (step 2b). The unit file stays in the
tree. It is not a removal, because a removed unit would make networkd's `Also=` fail to enable.

Checked end to end: the post-build output of the self-test's HOSTNAMED-off copy, then host `preset-all`: the wait-online
mask is in place, `preset-all` ignores it, wait-online is not linked to any wants directory, and networkd's links stay.

## The socket rule

For each enabled `.socket` in the tree (enabled = a wants or requires link names it, or the first matching preset line
says `enable`):

- its `Service=` (or the same-named `.service` when it has none) is in `OFF_SERVICES` (resolved, timesyncd, hostnamed,
  timedated): FAIL. The raw extracted root fails here, on `systemd-hostnamed.socket`:
  `socket systemd-hostnamed.socket is enabled and starts systemd-hostnamed.service, a daemon this image turns off`.
- an explicit `Service=` names a missing or masked unit (a dangling socket): FAIL.
- no `Service=` and no same-named service: NOTE (see the departures).

The enabled `.service` check: a `Type=dbus` unit fails; a `BusName=`-only unit is a NOTE. networkd is listed as a note.

The pass copy is the tree as the HOSTNAMED-off build makes it: the self-test removes `systemd-hostnamed.service`,
`systemd-hostnamed.socket`, its wants link, `/usr/lib/systemd/systemd-hostnamed` and `hostnamectl`, then runs the script.

## What is NOT proven

## Note: a dbus-named alias after the script (kept, ruled)

Host `preset-all` on the post-build output (the wait-online check above) also creates
`etc/systemd/system/dbus-org.freedesktop.network1.service`, an alias of networkd from its `Alias=` line. It is a
dbus-named link in the final image. This script cannot remove it: it runs before preset-all. The resolve1 and timesync1
aliases that the same run created come from daemons this PR turns off, so the real build does not get them. The fix is
a second hook that runs after presets (`BR2_ROOTFS_POST_FAKEROOT_SCRIPT`, which fs/common.mk runs after the pre-cmd hooks).
Ruled by the coordinator (2026-11-14): the alias stays. It is a zero-byte symlink to a live unit and nothing on the image
asks for that name, so it is not worth a second build hook. The claim "no dbus path in the image" therefore holds for the
post-build tree, plus this one alias.
