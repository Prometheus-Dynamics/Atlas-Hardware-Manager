# T2: `atlas-next bench-key`, the throwaway bench signing key

The coordinator's ruling (2026-11-14): the milestone's signed-bundle steps use a THROWAWAY bench key, made by this
tool, in the form both Atlas and `lemnos-ctl bundle` take (a raw Ed25519 seed file; see docs/prs/S1.md). No real
key is touched by anything. The seed is a test credential: never committed, never in a store, a log or a message.

## Command

    atlas-next bench-key <directory>

In the crate `crates/tools/next` (PR T1), using `atlas_bundle::Seed` (PR S1). It writes three NEW files in
`<directory>` and prints the key id and the three paths, nothing else:

| File | Content | Mode |
|---|---|---|
| `bench.seed` | the seed, as `Seed::write_new` writes it (64 hex and a newline) | 0600 |
| `bench.pub` | the public key: 64 lowercase hex and a newline (the form `lemnos-ctl bundle --pubkey` takes) | 0644 |
| `bench.keys` | the board's key-list line: `<64-hex public key> bench key, not for any released image` and a newline | 0644 |

Rules:
- `<directory>` must exist, must NOT be inside any git work tree (walk up from its canonical path: a `.git`
  entry, file or directory, in it or in any parent refuses, naming the repository's top), and on Unix must not be
  writable by group or others. Refusals say what to do instead.
- Nothing is overwritten: if any of the three files exists, nothing is written and the refusal names the file.
  If a later file fails after an earlier one was written, the ones written by this run are removed and the
  refusal says so.
- The seed's bytes never reach stdout, stderr, an error text or a log. The output is exactly: the key id (64 hex),
  then the three paths, one per line, each with a short label. `--json` gives the same as one JSON document
  (`key_id`, `seed_file`, `public_key_file`, `key_list_file`).
- The owner text is exactly `bench key, not for any released image`.
- Exit status as the tool's other commands (0 done, 1 refused, 2 usage).
- The command line help (and the usage text) says in one line that the key is for bench boards only.

If `atlas_bundle::Seed` lacks something needed (for example the public key as 64 hex), do NOT edit atlas-bundle:
derive it from what is public and say what was missing.

## Proof (mandatory)

Tests in the crate, calling the same command function the binary runs:
1. A run in a fresh temporary directory outside any repository: the three files exist with the stated modes;
   `Seed::read(bench.seed)` gives a seed whose `key_id_hex()` is the printed key id and whose public key is
   `bench.pub`'s content; `bench.keys` is exactly the line above; SHA-256 of the 32 public key bytes is the key id.
2. The output (text and `--json`) holds no part of the seed: compare against the seed file's hex, and its
   first and last 8 characters.
3. A directory inside a git work tree is refused and nothing is written (make a temporary directory with a `.git`
   directory in a parent; do not use this repository).
4. An existing `bench.seed`, `bench.pub` or `bench.keys` each refuses; nothing else is written or changed.
5. A group-writable directory is refused.
6. A record signed with the written seed (`sign_slot_record`) verifies under the public key in `bench.pub`.

Test directories come from the crate's existing temp-dir helper or `CARGO_TARGET_TMPDIR`; for proof 1 the
directory must not be under a git work tree, so check where the helper puts it and say so (CARGO_TARGET_TMPDIR is
inside the cargo target, which is outside the repository here and in CI's default layout is INSIDE it: handle both,
for instance with the `tempfile` crate if it is already in Cargo.lock).

## Not in this PR

The cycle's signed install, unsigned refusal and signed OFF steps (they need the L2 lock); any key that signs
something that leaves the bench; deleting the key (it goes with the bench boards' reflash at the milestone's end).

## As built

- `crates/tools/next/src/bench_key.rs` (new, `pub mod bench_key`): `run(directory, json, out)`, the command
  `execute` calls for `atlas-next bench-key <directory> [--json]`. Constants `SEED_FILE`, `PUBLIC_FILE`,
  `KEYS_FILE`, `OWNER`.
- `args.rs`: `Parsed::BenchKey { directory, json }`; `lib.rs`: usage line and dispatch.
- The public key as 64 hex is not on `atlas_bundle::Seed`: it comes from the public key's display form
  (`ed25519:<hex>`, `atlas_release::PublicKey`), checked for shape. Nothing else was missing.
- The text output is `key id: <hex>` then `seed file:`, `public key file:`, `key list file:` with absolute
  paths; `--json` gives `key_id`, `seed_file`, `public_key_file`, `key_list_file` (plus the usual `ok`,
  `code`, `messages`).
- A new dependency on `atlas-bundle`; dev-dependencies `atlas-release`, `sha2 0.11`, `tempfile 3` (all already in
  Cargo.lock).
- Tests: `crates/tools/next/tests/bench_key.rs` (eight tests, the six proofs, each in a `tempfile` directory
  under `$TMPDIR` or `/tmp`; a test stops when that directory is inside a git work tree) and a parser test in
  `args.rs`.
