## The security line and the scorecard field

J9 left the step-2 line and the scorecard field as "not read" (`0aa3f6f3`). Restored from the fact:

- **Step 2** (`crates/tools/next/src/cycle.rs`, `step_fingerprint`) reads `node.security()` and says
  `security on the board: <words>`. Its step text no longer says the mode is not read.
- **Scorecard text**: `Security on the board: <words>`; `not read` only if step 2 did not run.
- **Scorecard JSON**: `"security"` is `on`, `off`, `damaged`, or `not told`, and
  `"security_generation"` is the record's generation or `null`.
- Words: `NotTold` = "the board has not said"; `On` = "on: a signed session is needed" (with
  "(record generation N)" when given); `Off` = "off: a plain session is enough"; `Damaged` = "damaged:
  its security record cannot be read, so the board counts it as on".

The board-command "security off" first line stays removed (coordinator ruling, J9).

## Not done, and why

- **Sim knob for the four states.** The sim's comm core is Orion's stub `Board`, whose hello does
  not carry a security fact (only the real comm core, from its record, writes it). So against the
  sim only `NotTold` is reached. The other three are tested on constructed nodes, not the sim. A
  sim knob would need Orion's stub to carry a security record; that is Orion's to add, not a change
  to Atlas's sim.
- **`Finished.code`** is not read (T4 7c, waits for Lemnos's code).
- **The board image** keeps Orion `455a956e` (see The pin).
