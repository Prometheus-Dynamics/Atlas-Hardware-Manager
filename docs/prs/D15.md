# D15: The first-flash manifest, made by Atlas from the image

**Group:** D. Flashing

**Wave:** 6

**Needs:** D11, D13

**Runs:** cloud

Read `AGENTS.md` and `docs/design.md` first.

## Creates

- `crates/flash/xzdec` (new): the streaming xz for first-flash files. One image stream, optionally one signature record stream; the layout scan, the one-stream decode with liblzma's memory bound, and the record read. One decoder for the whole workspace.
- `crates/flash/image (edit)`: the manifest, the board check, the signature record and the signed message. The slot reader (`open`) moves to the shared decoder.
- `crates/flash/disk (edit)`: the card writer decodes the image stream only, through the shared decoder. `lzma-rs` is removed from the workspace.

## Build

- The build's only output is the first-flash `.img.xz`. When it is flashed, Atlas makes the transport `flash.json` (schema 1: `board`, `format` = the raw kind `disk`, `image.size`, `image.sha256` of the raw image, and `signature` when the file carries a record). The JSON is transport only. The signed object is a fixed binary message the board rebuilds: `"lemnos-first-flash\0"`, a u32 version, the board id, the kind, the raw size and the raw SHA-256.
- The file: stream 1 is the image; an optional stream 2 decodes to the 108-byte record (`LMNSSIG1`, algorithm 1, three zero bytes, key id, signature). Nothing else is accepted: a third stream, a second stream that is not one record, trailing bytes, non-zero padding between streams, a bad magic, algorithm or padding. Zero padding in multiples of four between the streams is accepted (the xz format's stream padding).
- Every reader decodes stream 1 only. The record is never written to storage.
- Atlas does not verify the signature. It reports unsigned, or signed with the key id, before pushing. The board's verdict (verified, not checked unsigned, not checked unknown key, refused) is a type in the crate for the flash flow to show.
- The board is read from the slots in the data partition: every `slots/*.json` must parse, be schema 3, and name one valid board. A wrong board is refused before the rest of the stream is decoded.
- The signature's place is the file's second stream, as the W1 contract (draft 2, `W1-actions.md`) defines it. Lemnos's board code does not implement draft 2 yet: the test vector and Atlas's own tests are the proof on this side.

## Decoder bound

- Dictionary: at most 8 MiB per block (the contract ceiling). A block declaring more is refused by name with the size found and the limit. A board may lower its own limit; `dictionary_within` gives the comparison, which belongs to D6.
- Memory: the dictionary plus 256 KiB (liblzma's memory limit is set to exactly that bound). At the ceiling, 8.25 MiB.
- Filters: LZMA2 only. Checks: none, CRC-32, CRC-64, SHA-256.

## Proof

- Tests (atlas-image): the message builder reproduces the W1 test vector's 85 bytes; the vector's signature verifies over them; the key id is SHA-256 of the public key; the record parser and writer reproduce the vector's 108 bytes; a throwaway key signs a generated two-stream image and the record round-trips; the layout refusals (third stream, junk second stream, wrong length, bad magic, trailing bytes, non-zero padding, zero padding accepted); the manifest of a two-stream file equals the single-stream manifest; the slot reader opens a two-stream file; a SHA-256 check is accepted; a 16 MiB dictionary is refused by name.
- Tests (disk): a two-stream file writes exactly stream 1, and the record bytes are never written; a 256 MiB single-block image and a two-stream 256 MiB image are written within a 96 MiB peak resident bound (Linux).
- Not run on a board. The Lemnos side is pending.
