## Build

- The build's only output stays the first-flash `.img.xz`. When it is flashed, Atlas makes the `flash.json` that Lemnos's `system.flash/1` takes (schema 1, `W1-actions.md`): `board`, `format`, `image.size` and `image.sha256` (the SHA-256 of the raw image), in one streamed pass. The board is read from the slots' `board` values in the data partition (the slot's `slots/<id>.json`), so the pass is refused early when it is for another board.
- `probe_board` is the early step: it stops as soon as the data partition is read. `flash_manifest` makes the manifest, with an optional target that refuses at the same point. `check_target` is the hard rule and says in plain words which board the image is for and which is connected.
- A detached `flash.sig` beside the image is carried along and reported by presence; its length is checked (64 bytes), its content is not verified.
- The decoder is liblzma through `xz2` (see the PR text): streamed, bounded by the dictionary, which is checked from the stream's index against 8 MiB before any decode.

## Proof

- Tests: manifest fields and bytes against values computed here; both image forms and both stream formats; a wrong board refused with both names; no slot, no board and two boards each refused with its own message; signature present and absent; the early read counted; truncated and hostile images refused with no scratch left; a 64 MiB single-block image read in bounded resident memory.
