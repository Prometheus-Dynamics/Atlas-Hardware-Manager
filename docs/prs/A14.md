# A14: The session carries calls while a transfer runs

**Group:** A. Foundation

**Needs:** A12

**Runs:** cloud

Read `AGENTS.md` and `docs/design.md` first.

## Creates

- `crates/board/session (edit)`: `long.rs` (the seam), `double.rs` (the test double), `tests/long.rs`
- `crates/board/files (edit)`: `transfer.rs` (the adapters), `push.rs` and `source.rs` (the push on the long path), one proof test in `tests/push.rs`

## Build

- A long operation is a transfer advanced in steps on the session's own thread, between its calls.
  `Handle::long(&Cancel, start)` starts it on the live client; the session steps it until it is
  `Done`, cancelled, or the session is lost.
- The seam is `atlas_session::SteppedTransfer<T>` (`step(wait)` returns `Step::Progress` or
  `Step::Done(T)`, `cancel()`). It names nothing of Orion. The start closure runs on the session
  thread and returns the transfer; the transfer keeps its own client handle.
- Fairness (named constants in `long.rs`): a turn runs the calls queued at its start, then one
  step of each running operation, each given `STEP_WAIT` = 50 ms. At most `MAX_LONG_OPERATIONS` = 4
  run at once; a fifth is parked and not stepped. While operations run, at most 64 waiting frames
  are taken per turn (`MAX_FRAMES_PER_TURN`, monitor.rs). Worst case for a short call: two turns of
  steps, 2 x 4 x 50 ms = 400 ms, plus the short calls queued ahead of it, for an adapter that honours
  its `wait`.
- Cancel is seen at the next step boundary, never mid-step. A caller that stops waiting (drops its
  future) cancels the same way.
- A lost session ends every running operation with `SessionError::Gone` and refuses every queued
  call the same way; nothing is stepped on another session. A replaced node gets no start and no
  step (operations live only inside one session).
- `atlas-files` runs a push as a long operation: one attempt per session, the same resume, the same
  "do not continue on a replaced board" rule and the same counters as before. The one read of the
  source that Orion's R2 `push_with` makes unnecessary is marked `// LOCK: Orion R2 push_with` in
  `source.rs`.

## Lock notes

- Orion 455a956e has no stepped push. `Files::push` is one blocking loop; its only hook while it runs
  is a progress callback that cannot return control. Calls cannot interleave with it at this lock, so
  the adapter for this lock (`transfer.rs`, `Blocking`) runs the whole file as one step and holds the
  session, as before. The structure is in place; the interleaving arrives with Orion R2.
- The stepped adapter for Orion R2 (`Files::start_push`, `Pushing::step`) is written against the
  announced shape behind the `orion-r2` feature, which is off by default. It does not compile at
  455a956e (four errors: `Pushed`, `Pushing`, `Files::start_push` are not there). The gate does not
  enable the feature.
- When the lock moves to R2: enable the feature, check the names marked `// LOCK:`, flip
  `TODAY_CALLS_WAIT_BEHIND_A_PUSH` to `false` in `crates/board/files/tests/push.rs`, and drop the
  `Blocking` adapter. The same move replaces the `push_with` read marked in `source.rs`.
- Files board-to-client (`Files::fetch`, `Offer`) is not here. It is the same seam: a fetch adapter
  for the R2 stepped form, when the lock moves.

## Proof

- `crates/board/session/tests/long.rs` (against the simulated node, with the double): a short call
  completes while a long operation is still running (order of events); two long operations and 100
  short calls all make progress and interleave; a cancel lands at a step boundary (exactly three steps,
  then `Cancelled`); a lost session ends the operation and the queued calls and nothing steps after;
  a replaced node gets no start and no step; a transfer that fails for good answers `Failed` and the
  session carries on; a fifth operation waits for a slot and is not stepped meanwhile.
- The existing push tests in `crates/board/files/tests/push.rs` pass unchanged.
- `a_call_issued_during_a_push_completes_only_after_it_today` documents the lock's behaviour: the call
  runs after the board commits. The `TODAY_CALLS_WAIT_BEHIND_A_PUSH` constant flips its expectation.
