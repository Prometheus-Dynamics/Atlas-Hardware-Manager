# S1: the signing seed, the key id and the bundle record signer, ahead of the L2 lock

The coordinator's ruling (2026-11-14): the key file that BOTH Atlas and Lemnos's `lemnos-ctl bundle` take is a raw
Ed25519 seed, 32 raw bytes or 64 hex characters. The key id is SHA-256 of the 32-byte raw public key derived from
it. A stated key id is checked against the derived one BEFORE anything is signed. There is no minisign reader
anywhere. This PR lands that part of draft PR 89 (`l2/bundle-record`) alone, because it depends on no Lemnos pin
and a bench key in the agreed form is needed before the lock. The writer, the inspector and the simulated board
stay as they are on `next`: nothing that exists changes its signature or behaviour here.

## What

One NEW module in `atlas-bundle` (`crates/core/bundle/src/seed.rs`), re-exported from `lib.rs`. Additive only:
`sign.rs`, `write.rs`, `inspect.rs` are not edited (PR 89 will move its `sign.rs` onto this module at the lock).

- `Seed`: the 32 bytes. Its `Debug` prints no key bytes (`Seed(..)`), it has no `Display`, and it is wiped on drop
  if the workspace already has `zeroize` in Cargo.lock (do not add the dependency for it otherwise; say which).
- `Seed::generate()`: from the OS random source, through what the workspace already uses (look at how tests and
  `atlas-release` make keys; add no new random crate if one is already in Cargo.lock).
- `Seed::read(path)`: the file is exactly 32 raw bytes, or 64 hex characters with optional surrounding whitespace
  and one trailing newline. Anything else is refused in words that name the path and the two accepted forms and
  NEVER quote the file's content. On Unix a file readable by group or others is refused, naming the mode it has
  and `chmod 600`.
- `Seed::write_new(path)`: writes 64 hex characters and a newline to a NEW file created with mode 0600
  (`create_new`: an existing file is never overwritten), parent directory must exist.
- `public_key()`, `key_id()` (SHA-256 of the raw public key, 32 bytes) and `key_id_hex()`.
- `check_key_id(stated_hex)`: refuses, naming both ids, when the stated id is not the derived one.
- `slot_message(slot_json)` and `sign_slot_record(seed, slot_json, stated_key_id: Option<&str>) -> [u8; 108]`:
  the `LMNSSIG1` record exactly as PR 89 makes it. Read PR 89's code for the layout and the message:
  `git show origin/l2/bundle-record:crates/core/bundle/src/sign.rs` (and what it uses from `atlas-image` and
  `atlas-release`; if `atlas_image::Record` or `atlas_release::public_key_for`/`sign_bytes` are not on `next`
  in the form PR 89 uses, build on what `next` has and say what differed). The message is
  `"lemnos-slot-bundle\0"` | u32 LE 1 | u32 LE length | the slot.json bytes. With a stated key id, the check runs
  first and nothing is signed on a mismatch.

## Proof (mandatory)

1. The vector, byte for byte: seed 0x07 repeated 32 times, manifest `{"id":"vector"}`; the message and the 108-byte
   record in hex are in Lemnos's docs: `git -C /run/media/sozo/bd1d96d9-fa81-4fac-b25e-193cfcac2dcb/Github/lemnos
   show origin/next:docs/slots.md` (the section "The signed message", the vector lines) and in PR 89's tests
   (`git show origin/l2/bundle-record:crates/core/bundle/tests/bundle.rs`). The test holds the hex as constants.
2. Seed file: 32 raw bytes reads; 64 hex reads (with and without the newline); 31 bytes, 63 hex, 64 non-hex and an
   empty file are each refused, and the refusal's text holds none of the file's content; a 0644 file is refused.
3. `write_new` makes a 0600 file that `read` gives back as the same seed, and refuses to overwrite.
4. `check_key_id`: the right id passes; a wrong one is refused naming both; `sign_slot_record` with a wrong stated
   id returns the refusal and signs nothing.
5. `format!("{seed:?}")` holds no byte of the seed (test with a seed of a recognisable pattern).

No private key and no seed is committed: every test makes its own or uses the public vector seed (0x07 x 32),
which is published in Lemnos's docs and guards nothing.

## Not in this PR

The `bench-key` command (it goes into `atlas-next slots`, PR T1's crate, once that is on `next`); PR 89's writer,
inspector and simulated board; any key that signs something that leaves the bench.
