## Build

- Kernel console: for each product B11 touched (the ZERO 3E, ROCK 5C and ROCK 4D, base and bring-up) and for `raze-base`, read the kernel's `console=` from the files, and the tty the configured getty is on. Where they are the same tty, say so in a comment. Where systemd's getty generator would start a second getty on the kernel console, mask it in the product's fragment in the way the product already expresses units. Where the console cannot be read from the files, record it as open.
- Persistent SSH host key: a bring-up product keeps dropbear's key on the data partition, through the unit's `-r` argument, with the unit ordered after the data mount. A base product's Orion keeps its key on the data partition too, through its own config; if Orion itself needs a change, it is a finding and not a change here.
- Shared lines go in one shared component, not one copy per bring-up product.

## Open

- Raze kernel console: not set by any file on next (the image's own cmdline.txt, Gaia F10). Unknown: which `console=` the Raze boot gets. Dev's `console=serial0,115200 console=tty1` would add serial-getty@ttyAMA10 next to ttyGS0, and tty1 is a keyboard getty. Decide with the cmdline; then mask if needed.
- Gaia has no mask form for units: a component's `[[install]]` copies files and `[[services]]` takes `enable` only. A mask (a /dev/null symlink) needs Gaia's form.
- cubie-a7-bringup: kernel console ttyS0 has no configured getty, so only systemd's generator starts one; its login policy is not written.
- cubie-a7-bringup: no dropbear.default, so dropbear runs without -s.
