## Build

- `open_link` finds a claimed vendor interface by its string (D12), refuses anything but exactly one bulk IN and one bulk OUT endpoint (the refusal names what was found, and nothing is claimed), claims it, and splits it into two independent halves.
- The halves are byte streams. USB packet boundaries are not visible, except through the zero-length packet option below.
- Works through nusb on Linux, Windows and macOS. No OS-specific code was added.
- The simulated bus gives the same halves, with a `SimPeer` for the test to play the board.

## What a caller gets

Async (the primary API, from tokio's traits):

- `Link` (returned by `open_link`): `into_parts()` gives the two async halves; `into_blocking()` gives the blocking halves.
- `LinkReader`: `tokio::io::AsyncRead`, `Send + 'static`.
- `LinkWriter`: `tokio::io::AsyncWrite`, `Send + 'static`. `flush` waits until every queued transfer has completed. `shutdown` is a flush; the link stays open.

Blocking (`std::io::Read` and `std::io::Write`, and the two traits mirrored for Orion):

- `Link::into_blocking()` gives `(BlockingReader, BlockingWriter)`. Each owns a current-thread tokio runtime that this call creates. No thread is started, and no runtime is spawned inside a library call. Call it from outside any tokio runtime.
- `BlockingReader`: `std::io::Read`, `Send + 'static`, and `LinkRead`.
- `BlockingWriter`: `std::io::Write`, `Send + 'static`, and `LinkWrite`.
- `LinkRead` (`// LOCK: Orion F12a LinkRead/LinkWrite`): `fn read(&mut self, into: &mut [u8]) -> io::Result<usize>`. It blocks until bytes arrive. `Ok(0)` is nothing yet (a zero-length packet), never the end.
- `LinkWrite` (same LOCK): `fn write_all(&mut self, bytes: &[u8]) -> io::Result<()>`. It returns once every byte has been handed to the device, or fails.
- Both are mirrored locally and marked for replacement by impls of Orion's traits at the lock move. Nothing here depends on Orion.

Options and helpers:

- `LinkOptions { zero_length, read_timeout, write_timeout }`. Defaults: `ZeroLength::Never`, no read timeout, a write timeout of the bulk timeout (5 s).
- `is_device_gone(&io::Error)`, `usb_error(&io::Error) -> Option<&UsbError>`.
- Constants with reasons: `READ_IN_FLIGHT` = 8 (one packet per IN transfer), `WRITE_TRANSFER` = 16 KiB (a multiple of every bulk packet size), `WRITE_IN_FLIGHT` = 4 (memory bound 64 KiB).
- `UsbIo::into_halves` and the traits `BulkRead` and `BulkWrite` (the halves' interface on nusb and on the simulated bus). `LinkOptions` is passed into `into_halves`.
- Simulated bus: `SimBus::peer(location) -> Option<SimPeer>`. `SimPeer` has `send_packet` (at most 512 bytes, empty is a zero-length packet), `recv_packet` (the next packet the PC wrote, boundaries kept), `queued_from_pc`, and `set_stall(direction, bool)`. Constants `SIM_PACKET_BYTES` = 512 and `SIM_BUFFER_BYTES` = 8 KiB.

## Decisions

**Zero-length packets, default `Never`.** A device-side byte stream (FunctionFS) reads a zero-length packet as a zero-length read, which a byte reader treats as end-of-stream. So the default never sends one. `ZeroLength::OnFlush` sends a zero-length packet on `flush` when the last bytes ended on a full packet, for a peer that reads by transfer. nusb's own `EndpointWrite::submit_end` takes the same position. A zero-length packet from the device is never end-of-stream: a read returns `Ok(0)` (blocking form) or loops (async form).

**Primary API: async.** nusb transfers and the crate's `UsbIo` are async. The blocking halves wrap the same halves on their own current-thread runtime.

**Reads.** Each IN transfer asks for one packet, so a read returns as soon as a packet arrives and never waits to fill a buffer. Eight are kept queued on the device. A read has no timeout by default: a board may be quiet indefinitely.

**Writes.** A write is accepted once its transfer is queued. It waits while four are queued. A write error is sticky (stall, timeout, unplug): the stream position is unknown, so every later call fails with the same error.

**Unplug.** Both halves report `UsbError::Disconnected` as an `io::Error` of kind `NotConnected` (`is_device_gone` is true). It is sticky on each half. A read or write already waiting is ended by the transfer completing with the disconnect error (nusb) or by the simulated unplug. A half that is idle learns on its next call; a write accepted after the unplug fails at the next flush.

**Stalls and timeouts.** A read stall is reported and is not sticky. A read timeout (only if set) loses no bytes and can be retried. A write stall or timeout is sticky.

**Stopping a blocked read.** Drop the blocking write half. It sets a shared flag and wakes the reader; the blocked `read` returns an error at once (kind `Other`, not gone), cancels its queued IN transfers, and drops its endpoint. The interface claim is released when both halves are gone. Dropping the blocking reader instead drops its endpoint, which cancels its queued transfers; bytes already received into a cancelled transfer are lost. The async halves do not share this flag: dropping one async half leaves the other working, and dropping a half with a transfer pending cancels that transfer.

**Dropping a half.** Dropping one half never affects the other, except as stated above for the blocking write half. Dropping the last half releases the claim. The gauges count the device once, until both halves are gone.

## Proof

`cargo test -p atlas-usb` on the simulated bus (`tests/link.rs`, 23 tests), all passing:

- bytes in order both ways across packet boundaries, including zero-length packets; partial reads return what arrived; a zero-length packet is not end-of-stream
- large writes split and arriving whole; a write ending on a full packet sends nothing extra by default, and a zero-length packet on flush with `OnFlush`
- unplug while a read is pending and while a write is pending: both halves error with the gone kind; sticky afterwards
- dropping one half leaves the other working; dropping both releases the claim (gauges)
- wrong endpoints (two bulk IN, an interrupt endpoint, no bulk OUT) refused with the endpoints named, nothing claimed
- back-pressure: a fast writer is held back; queued bytes stay within the buffer and the in-flight bound
- stall: reported, not sticky for reads, sticky for writes; read timeout loses nothing; write timeout is sticky
- blocking halves: byte exchange both ways; `read` blocks and returns `Ok(0)` for a zero-length packet; a blocked read is stopped by dropping the write half, within the deadline, and releases the claim; a read blocked on one thread does not delay a write on another; unplug while blocked is gone, not a timeout; alternating write and read against a slow peer, 20 rounds; no zero-length packet from a plain write

Gate: see the PR thread for `gate passed` and CI.

## Not proven

- Nothing here ran on Windows or macOS. nusb's backend is the same code path, but the transfer and disconnect behaviour there is untested.
- Nothing ran on a board. The nusb halves (`cancel_all`, transfer completion on disconnect, the one-packet IN request) are compiled but unexercised against a real endpoint. The simulated bus stands in for every behaviour above.
- Whether a FunctionFS function on the board completes a read on a full packet with no zero-length packet after it. The default (`Never`) depends on this; the board run decides whether `OnFlush` is needed.
- The write timeout under a real slow reader: back-pressure is tested on the simulated bus only.
- The Orion join: `LinkRead` and `LinkWrite` are local mirrors. They are replaced by impls of Orion's traits at the lock move (`LOCK: Orion F12a`).
- Nothing else in the crate depends on these halves yet.
