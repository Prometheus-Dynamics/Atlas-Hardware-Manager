## Emulation (Gaia a739afc0 `scripts/qemu-rpi-slots.sh --profile board`, run from a copy of that rev; no pin move)

Kernel: Gaia's virt kernel (board-proof/vk-udc2). Setup: eMMC with boot areas, a firmware-armed watchdog at
`--watchdog-scale 459`, and the vudc as the UDC. The runner records each of these per boot as unlike the board.

1. **Stock host.** The first boot of the disk image enumerates as 1d6b:0104 with serial a317bcbee5226d57 (the board
   file's ids) and functions ffs, NCM and ACM. The host leases 172.31.209.222/29 from .217, the lease carries no host
   configuration, ping works, and the TCP connect to .217:9200 works.
2. **Slot pass under the real unit.**
   - A boots from eMMC with build clean, medium emmc and booted_medium emmc, and no seccomp traces.
   - /data grows to 15.9G.
   - Live `install_file` of build10's signed bundle (dev.1303): all 26,288,640 bytes, signature verified, job done,
     state staged.
   - `trial` makes lemnos-restart reboot the board. A's slot-init turns that reboot into `0 tryboot`, which costs one
     extra restart of about 1 s.
   - B boots from bay1 on trial and confirms itself (`by: auto`). B becomes the default and A the previous.
   - After a power cut, B boots again as the default.

   Two steps of this pass are not like the board:
   - **(a) Deadline scaled.** The call deadline was scaled to 9200 ms (2000 ms × 4.59, the measured slowdown). At
     2000 ms, a tick of install_file runs past the deadline at about 5 MB under TCG, and the job ends interrupted.
   - **(b) Directory owner set.** /data/slots/bootfiles was given to lemnos offline. Without that, the finish fails
     with "the slot's boot files: Permission denied" (see below).

## What stops a flash (open)

- **BOOTFILES-OWNER (Lemnos).**
  - The first-flash data image makes /data/slots/bootfiles root:root 0755.
  - slot-init's `give_state_dirs` gives the lemnos user only the state dir and the images dir.
  - So the first install whose boot files differ from those stored fails. That includes any real update.
  - build10's data image is the same, so this is not new with PM10.
  - Reported to the coordinator. It needs a Lemnos rev; Atlas adds no workaround without a ruling.
- **The install's call deadline on the board.** Unproven. In emulation the 2000 ms deadline is too short; the board's
  CPU is about 4.6× faster.
- **Emulation-only console stall.** In 2 of 4 build11 board-profile boots, the ttyAMA0 getty stopped after
  systemd-executor's terminal-size query (ESC[6n) and never offered a login. That was 0 of 1 for build10 and 0 of 1
  with lemnosd masked. The pass used `systemd.debug_shell=/dev/ttyAMA0`. Recorded, not chased.
