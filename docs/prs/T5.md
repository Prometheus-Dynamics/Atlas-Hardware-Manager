# T5: Orion's refusals carried as a typed value, not matched by their words

T3 recognises "this PC's key is not enrolled" by the word "denied" in a text, because Orion's refusal crosses
`atlas-session` (and `atlas-board-slots`) as a `String` (`SessionError::Failed(String)`, crates/board/session/src/
monitor.rs ~100). The coordinator's ruling (2026-11-14): no matching on words. Carry the refusal as a typed value.

## What

- In `atlas-session`: where an Orion client error becomes a session error today, keep its KIND as a typed value
  beside the text: an enum of the Orion client error variants Atlas cares about (at least `Denied`, and whatever
  else the pinned Orion's `ClientError`/`Error` distinguishes that a caller would act on: read them in the cargo
  checkout of the pinned rev, `~/.cargo/git/checkouts/orion-*/<short rev>/crates/client/`), plus Orion's numeric
  code if the error carries one, plus the text unchanged. A variant Atlas does not name maps to `Other`. The text
  is still shown to people as it is.
- Through `atlas-board-slots` (and any other crate between the session and the tool on this path): keep the kind,
  do not flatten to a String.
- In `atlas-next`: recognise "not enrolled" from the kind (`Denied`), never from the text. Remove the word match.
- Keep every public name that other crates use; where a signature must change, change its callers in the same PR.

## Proof (mandatory)

1. A test that a Denied refusal whose TEXT is reworded (for example a stub that returns `Denied` with text "no")
   still maps to the not-enrolled line, and that a non-Denied error whose text contains "denied" does NOT.
2. The T3 security-on tests still pass unchanged (security.rs).
3. Every existing test in the workspace passes (the gate).

## Not in this PR

Any change of behaviour other than the matching; the cycle runner (T4, in parallel: it may touch the same files in
crates/tools/next, so keep this PR's changes there minimal and merge first).
