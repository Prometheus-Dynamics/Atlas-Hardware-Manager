# T5: Orion's refusals carried as a typed value, not matched by their words

T3 recognises "this PC's key is not enrolled" by the word "denied" in a text, because Orion's refusal crosses
`atlas-session` (and `atlas-board-slots`) as a `String` (`SessionError::Failed(String)`, crates/board/session/src/
monitor.rs ~100). The coordinator's ruling (2026-11-14): no matching on words. Carry the refusal as a typed value.

## What

- In `atlas-session`: where an Orion client error becomes a session error today, keep its KIND as a typed value
  beside the text: an enum of the Orion client error variants Atlas cares about (at least `Denied`, and whatever
  else the pinned Orion's `ClientError`/`Error` distinguishes that a caller would act on: read them in the cargo
  checkout of the pinned rev, `~/.cargo/git/checkouts/orion-*/<short rev>/crates/client/`), plus Orion's numeric
  code if the error carries one, plus the text unchanged. A variant Atlas does not name maps to `Other`. The text
  is still shown to people as it is.
- Through `atlas-board-slots` (and any other crate between the session and the tool on this path): keep the kind,
  do not flatten to a String.
- In `atlas-next`: recognise "not enrolled" from the kind (`Denied`), never from the text. Remove the word match.
- Keep every public name that other crates use; where a signature must change, change its callers in the same PR.

## Proof (mandatory)

1. A test that a Denied refusal whose TEXT is reworded (for example a stub that returns `Denied` with text "no")
   still maps to the not-enrolled line, and that a non-Denied error whose text contains "denied" does NOT.
2. The T3 security-on tests still pass unchanged (security.rs).
3. Every existing test in the workspace passes (the gate).

## Not in this PR

Any change of behaviour other than the matching; the cycle runner (T4, in parallel: it may touch the same files in
crates/tools/next, so keep this PR's changes there minimal and merge first).

## As built

- `crates/board/session/src/failure.rs`: `Failure { kind, code, text }` and `FailureKind { Denied, OtherKey,
  Refused, Other }`, exported from `atlas-session`. Built from Orion's own error (`orion::Error`, `ClientError`,
  and the comm core's `orion::types::Error`) at the pinned rev fd61df3, `crates/client/connect/src/error.rs`:
  `ClientError::Denied` and `Refused(types::Error::Denied)` are `Denied`; `OtherKey` is `OtherKey`; any other
  `Refused(code)` is `Refused` with its code; everything else (`Io`, `Lost`, `Protocol`, `TooLarge`,
  `NoDescriptors`, topic errors) is `Other`. The text is the text the error gave before (unchanged).
  `From<String>` and `From<&str>` make an `Other` failure from text only.
- `SessionError::Failed(Failure)` and `StepError::Failed(Failure)` (were `String`). `SessionError::Gone` stays text.
- `ActionError::Refused(Failure)`, `Failed(Failure)`, `Unknown { reason: Failure }`, `Lost { reason: Failure }`
  (were `String`). `ActionError::failure()` returns the typed value. Board's own words (`Outcome::Rejected` and the
  rest of `ended`) are `Other` failures, so the board's words no longer read as Orion's refusal.
- `SlotError::failure()` (`atlas-board-slots`) returns the same value for `SlotError::Board`.
- `crates/tools/next/src/commands.rs`: `Refusal` has `denied: bool`, set from `SlotError::failure()` by
  `FailureKind::Denied`. The word match (`denied_by_board`) is gone. `enrol` still matches the variant directly.
- Crates changed beyond the session and tool, only for the signature change: `atlas-actions` (`board.rs`,
  `error.rs`, `tests/actions.rs`), `atlas-board-slots` (`lib.rs`, `install.rs`), `atlas-files` (`transfer.rs`,
  `push.rs`), `atlas-topics` (`hardware.rs`), `atlas-access` (`kind.rs`: `AccessError::Refused` stays a `String`;
  the kind is flattened there, and access is not on the tool's path).
- Dev dependency added: `atlas-actions` in `crates/tools/next/Cargo.toml` (the tool's test builds an `ActionError`).

Proofs (run in the gate):
- `crates/board/session/tests/session.rs`: `a_denied_refusal_keeps_its_kind_whatever_its_words` (a `Denied("no")`
  stub is `Denied`, text "no"; the comm core's `denied` is `Denied` with its code), and
  `a_non_denied_failure_whose_text_says_denied_is_not_denied` (`Protocol("denied")` is `Other`).
- `crates/board/session/src/failure.rs` unit tests (classification of each Orion variant).
- `crates/tools/next/src/commands.rs` tests: `a_denied_refusal_marks_the_not_enrolled_line_whatever_its_words`
  and `a_refusal_that_is_not_denied_does_not_mark_it_even_if_its_words_say_denied`.
- The T3 security tests (`crates/tools/next/tests/security.rs`) and the rest of the workspace: gate.
