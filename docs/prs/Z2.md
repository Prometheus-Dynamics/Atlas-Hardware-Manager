## Watchdog timing windows (merge condition, coordinator's review)

Pins read: U-Boot v2026.10 (research/u-boot 55084065); kernel stable 7595a62d (the commit the checker applies the
series to; family.toml names v7.3.3, whose tag is not in that repo: NOT VERIFIED that the two are the same tree);
Lemnos next 82f6c075 (fetched into the scratch clone; the pinned rev 31e0f736 is NOT VERIFIED for these lines).

### Arithmetic (DesignWare dw-wdt, 24 MHz on rk3566/rk3568)
- The counter has 16 TOPs: TOP = 2^(16+i) cycles, i = 0..15 (dw_wdt.c:51-63). At 24 MHz: i=13 is 22.37 s,
  i=15 is 89.48 s (the maximum). Clock: TCLK_WDT_NS = xin24m (kernel clk-rk3568.c:1208); U-Boot OSC_HZ = 24 MHz
  (cru_rk3568.h:12).
- U-Boot's `designware_wdt_settimeout` takes **milliseconds** (designware_wdt.c:94-99, comment "set timer in
  miliseconds"); `i = fls(ms * clk_khz - 1) - 16`, clamped to 0..15 (designware_wdt.c:31-40).
- Kernel `dw_wdt_set_timeout` takes seconds and picks the first TOP whose sec >= the request (dw_wdt.c:123-142, 198-242).

### What each request becomes on the ZERO 3E (and what Lemnos's timeout_s = 15 becomes)
| Who | Request | Applied on hardware | Read back |
|---|---|---|---|
| U-Boot arm (wdt-uclass.c:88, 60000 ms) | 60 s | 60000 x 24000 = 1.44e9 cycles -> fls 31 -> i clamped 15 -> **89.48 s** | - |
| slot-init (sys.rs:20, 65-83), DOG_SECONDS = 15 | 15 s | fls(15 x 24e6) -> i 13 -> **22.37 s** | kernel `wdd->timeout` = 22 (dw_wdt.c:237-238: 15000 <= max_hw_heartbeat_ms, so the TOP's sec) |
| lemnosd hw-watchdog, timeout_s = 15 (lib.rs:306-310, clamp to the device range, then read back) | 15 s | **22.37 s** | 22 |
| systemd, RuntimeWatchdogSec=16s (bringup-alive 10-watchdog.conf:24) | 16 s | **22.37 s** (16 > 11.18 s, the i=12 TOP) | 22 |

### THE KNOWN BLOCKER for a first ZERO 3E boot (not a Z2 code change; Lemnos fixes it in a later rev)
slot-init refuses any applied timeout above its own 15 s (sys.rs:77-82: `timeout > DOG_SECONDS` -> Err). On the ZERO 3E
the 15 s request is applied as 22 s, so with Lemnos 82f6c075 every rk35xx slot boot takes the `NO WATCHDOG` path: the
file is dropped without the magic character (Rust opens are close-on-exec), the device stays armed at 22 s and nobody
feeds it. The board resets about 22 s after that open unless lemnosd binds and feeds first. Logged line: `slot-init:
NO WATCHDOG: ...` (sys.rs:225-227). **Until the Lemnos fix is pinned, do not boot a first ZERO 3E image: it would run
the boot unfed against a 22 s period.** Lemnos's fix is theirs; Z2 changes no code for it.
lemnosd is not affected the same way: it clamps to the device's range and reads the applied value back (lib.rs:37-39),
and feeds at half the applied timeout (lib.rs:50-51), so about every 11 s on the ZERO 3E.

### Windows, in order (ZERO 3E bench image: slot-init boot)
1. **U-Boot arm: 89.48 s.** Armed at watchdog probe (wdt-uclass.c:233-248 autostart; CONFIG_WATCHDOG_AUTOSTART=y in
   u-boot.fragment:61). U-Boot feeds every reset_period (1 s) from `schedule()` (cyclic.c:121-131), which is called from the
   bootdelay wait, the cli, and image copy (image-board.c:178). The filesystem read path and `booti` make no `schedule()`
   call (fs/, drivers/mmc/, cmd/booti.c, arch/arm/lib/bootm.c: none), so the extlinux load runs without a feed.
2. **Kernel probe -> slot-init's open.** The kernel reads the armed TOP back (dw_wdt.c:641-643) and, with
   CONFIG_WATCHDOG_HANDLE_BOOT_ENABLED (default y; not overridden in the defconfig or our fragment), feeds the boot-armed
   device itself until the open deadline: `open_timeout` = 30 s from registration (watchdog_dev.c:1088; the pings stop
   after it at :204-215). Condition: CONFIG_DW_WATCHDOG=y (checked by open_timeout_rule in check-devices.sh).
3. **slot-init arms at its start** (boot.rs:185-186, "armed as soon as /dev exists"; sys.rs:65-83) and feeds every 5 s
   (sys.rs:20). With the blocker above it does not feed (see the NO WATCHDOG section).
4. **exec / switch_root:** the fd closes without the magic character, so the device keeps its applied timeout and is not
   fed. **UNFED gap: 1.0 s in QEMU (the coordinator's figure, not measured on a board).**
5. **lemnosd bind:** the hw-watchdog driver opens `/dev/watchdog0` (lib.rs:150-158, write-only), sets timeout_s = 15
   (applied 22) and feeds from its first healthy tick (lib.rs:50-56; host.rs:428-432; healthy = loop turned within 10 s
   and socket answered within 5 s, liveness.rs:12-18). The data-partition grow runs in lemnosd after the bind.

Bench image through slot-init: products/zero-3e-bench/product.toml names `initramfs = ["lemnos-slot-init"]` and
`recipe = "slot-disk"`. That the Gaia slot-disk recipe installs it as the slot's initramfs: NOT VERIFIED here (the Gaia
output is not in the tree). If it does not, the kernel-fed window runs to lemnosd's bind and 30 s may be too short:
report that before any decision.

### First-boot measurement list (every rk35xx board, first boot with partition growth; NOT VERIFIED until measured)
1. U-Boot's last feed -> watchdog driver probe (boot log: the last U-Boot feed, the dw_wdt probe line).
2. Driver probe -> slot-init's open (kernel log vs the initramfs "armed" line). Must be <= 30 s.
3. slot-init's last feed -> lemnosd's open at bind -> lemnosd's first feed (journal and initramfs log).
4. Bind -> running-ok (the lemnosd journal; M41b does not exist at the Lemnos rev read).
5. The applied timeout read back at each open (`/sys/class/watchdog/watchdog0/timeout`; expected 22 on the ZERO 3E).
6. Whether `slot-init: NO WATCHDOG` was logged (expected YES on the ZERO 3E with Lemnos 82f6c075; any other value is a finding).
