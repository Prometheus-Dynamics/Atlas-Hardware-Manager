## Build

- `slot.json` is schema 3: `product`, `version`, optional `variant`, and `board` (the board the slot was built for), with `id`, `kernel`, `display_name`, `image.*`, `verity.*` and `boot.files` as before. The `family` key is gone. `slot.sig` still signs the exact bytes of `slot.json`.
- A bundle whose `board` is not the target board is refused before anything is pushed, with a message that names both.
- The source seam takes what the image actually carries: the verity root hash and the data length from the slot's manifest, not a full verity table. `atlas-bundle` gains the adapter over `atlas-image`, so a bundle is made from a first-flash image in one call.

## Proof

Tests: a bundle made from a test image through `atlas-image` matches its parts; a slot for another board is refused; schema 2 input is refused by name.
